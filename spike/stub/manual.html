Milestone L0, Appendix B of the implementation plan: the checks that need a person and a real Chrome.

Stub: checking…

Before you start

  1. This Chrome must be a fresh profile with the unpacked extension “godir spike” loaded, as manual.sh describes. chrome://extensions should list it without errors.
  2. Keep this tab open. Do each step in a new tab, then come back here.
  3. Type what a step shows into the address bar by hand and press Enter. Don't paste it, and don't pick a suggestion. If Chrome adds highlighted text after what you typed, press Delete once before Enter, so that only your own text is sent.
  4. Follow the order, and until step C is recorded type nothing that starts with go/ except what a step asks for. Chrome learns the host once and this profile can't unlearn it. After a slip, start again in a new profile.
  5. The page watches the stub's request log and marks a step when its request arrives. You still say what you saw; correct the outcome if it was filled in wrongly.
  6. Answers are kept in this profile and saved to the results file after every change, while the stub is running. If this tab is ever closed, or shows the extension's “The Directory did not answer” page, open http://localhost:4655/-/spike/manual again: nothing is lost.

This browser

The first two are filled in from what the browser reports. Compare with chrome://version and correct them if needed. For the third, run dscacheutil -q host -a name go in a Terminal and enter what it prints, or “no output”. It tells a later reader whether a machine called go exists on this network (checks 7 and 16).

    When you are done

    1. Click “Save results” once more and check the line under it says “Saved”.
    2. Quit the test Chrome: click its window, then Cmd+Q. Your everyday Chrome, if it is open, is a separate app in the Dock and is not affected.
    3. In the Terminal where you set P, remove the throwaway profile: rm -rf "$P"
    4. In the Terminal that runs manual.sh, press Ctrl+C.
